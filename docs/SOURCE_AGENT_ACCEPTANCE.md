新协议的选区任务只调用 `edit_file`，随后回复，达到一次写入加一次最终回复。批量任务调用 `read_file`、一次 `edit_file`，随后回复。旧协议选区任务读取完整块、回传完整块并调用浏览器检查；批量任务需要额外搜索、读取和分批块写入。两边最终 HTML 均与预期逐字符相同，没有工具修改错误。

批量任务两边各有一次失败请求重试；API 请求数和耗时包含重试，逻辑轮次不包含。测试时本机也运行了回归检查，缓存状态和网关延迟会影响数字。这是合成文章上的单次样本，不代表所有文章、模型和网关的稳定收益。

## 保留的限制

此次开放的是授权源码文件接口，未开放脚本执行。浏览器检查仍按任务性质由模型选用；结构调整、主题应用、用户要求或兼容性有疑点时应检查，简单缩进和颜色调整仅做结构检查。规则提示中的旧“每轮必须浏览器检查”冲突已修正，新协议的实际缩进请求未再额外调用浏览器检查。

内联图片以稳定占位符编辑，HTML 未被自动格式化。源码写入产生结构 warning 时会保留候选供修复；只读、版本冲突、重叠修改、未知占位符和主题严格验证失败则拒绝整批写入。
