## 规范到提示词的映射

| 官方章节 | 需要守住的边界 | 保留的设计空间 / 例外 |
| --- | --- | --- |
| 1.1 opacity | 不将内容图片设为完全透明并用 SVG 背景图替代 | 保留真实可替换的图片；不扩展为禁止所有透明装饰 |
| 1.2 caret-color | 有内容节点的光标不能完全透明 | 空段落检测例外 |
| 1.3 line-height | 多行文字不可重叠，需考虑继承与真实换行 | 无文字图片拼接、实际单行是文档例外；报告需复核 |
| 1.4 width | 多屏居中、溢出、宽度比例；图片原始尺寸真实 | 固定尺寸、Flex/Grid、定位本身不是违规；有意滚动或裁剪可按规则豁免 |
| 1.5 height | 不因零高度或固定高度裁掉正文 | SVG 内部、SVG 交互容器、无文字是零高度例外；可滚动查看是文档的溢出例外 |
| 1.6 text-align | start/end 与祖先对齐方向冲突时有跨终端差异 | 与外层方向一致时不触发检测；新生成内容优先明确对齐值 |
| 1.7 begin | SVG touchstart 动画同时支持 click | 声明式动画不是 JavaScript；仍需满足项目输出通道要求 |
| 1.8 pre | 超宽且不能横向滚动的内容有阅读风险 | 可滚动代码块、换行或未超宽的 pre 不触发；无需额外标记，width 豁免不影响本条 |
| 2.1 嵌套 | 达到第 15 层后检查并精简无信息的重复包装 | 深度本身不等于违规；保留必要布局、背景与媒体结构 |
| 2.2–2.3 leaf | span[leaf] 不包块级元素；nodeleaf 仅承载指定组件 | 不要求所有普通文章统一添加 leaf 或强制 section 根节点 |
| 3 字体 | 默认不新增字体族，必要时使用官方完整默认栈 | 自主设计字号、字重、字距、层级，不依赖外部字体 |
| 4.1 颜色 | 深色模式下保持可读与舒适，兼顾低对比度与过高亮度；文字渐变背景先混合为纯色再转换 | 平台不限制配色；无文字的装饰渐变可保留，不自行编造固定对比度阈值 |
| 4.2.1 共用背景 | 多个文本共用的背景放在共同容器上，避免重复背景造成转换差异 | 按真实组件组织背景与文字 |
| 4.2.2 定位、变形与结构 | 严禁通过绝对定位或变形破坏视觉与 DOM 顺序，或将文字移到没有从属关系的背景区域 | 定位、变形与叠层须同时满足顺序和背景从属要求；width 豁免不影响本条 |
| 4.3 图片 | 谨慎使用图片纯文本及透明深色图；理解背景图补色 | 保留用户已有海报、Logo、截图；不把建议变成删除依据 |
| 4.4 SVG | SVG 不自动进行深色转换 | currentColor 或适合的底色；允许内联矢量装饰与示意图 |
| 4.5–4.6 豁免 | data-no-dark 仅当前节点；data-ignore-dm 仅当前节点指定规则；不新增 !important | 充分确认视觉效果后局部使用，不能用祖先标记豁免全篇 |

`redundant-node` 的“子节点 > 20 且空节点 > 15”来自官方 `rules-text.ts` 的预留文案，源码明确标注目前没有规范章节或 CLI 实现。重写后将避免空节点占位保留为项目排版建议，不把该阈值虚构成官方正文新增规则或当前引擎已经执行的检查。

## 文档要求与引擎结果的区别

1. 文档与 `nest.ts` 现均以第 15 层作为开始检查冗余结构的阈值，最终结果键为 `nestNodes`。无冗余结构的深嵌套不应仅凭深度判为违规。
2. 文档列出实际单行的小行高例外；`layout.ts` 对计算行高为零仍有直接命中分支。新版会归并同一视觉行的 Range 片段，减少嵌套强调造成的误报；对仍命中的项目保留原始报告并复核实际视觉效果。
3. 源码中存在 `font-family` 检查函数与 leaf、冗余节点规则文案，不代表当前引擎入口已经执行全部检查。当前 `collect.ts` 未调用字体检查，`index.ts` 也没有完整接入所有结构规则。通过报告只能说明当前检测未发现问题，不能作为违反文档要求的许可。
4. 当前默认布局测量宽度为 585、677、375 px，不代表已覆盖所有手机与微信客户端。引擎聚合结果可能不包含详细测量数据；模型只能引用工具实际返回的证据，不能编造真机测试或视觉复核结果。
5. `data-ignore-width` 的节点检测会查询祖先属性，段落溢出候选则另行检查段落自身标记。应只在必要范围按文档使用，不能把祖先豁免当作消除所有段落报告的保证。`data-ignore-dm` 使用文档公开的 `low-contrast`、`text-bg-gradient`，不使用未公开值绕过报告。

## 项目实现边界

[规则提示词](../rule.prompt.md)按任务目标、官方四章、豁免范围、用户与项目约束、检测流程及文本附件重新组织。官方要求与用户自定规则分别标明来源；布局建议不是强制样式模板，检测实现细节不作为放宽规范的依据。

重写时保留以下既有用户约定与项目约束：

| 约束 | 保留方式 |
| --- | --- |
| 文案与语义 | 默认只改排版；授权后才修改文案；保留事实、阅读顺序及局部强调 |
| 设计自由与默认值 | 可自主设计并使用 Flex/Grid、背景装饰和内联 SVG；正文默认值限普通正文，主题严格契约限对应任务 |
| 绝对定位 | 慎用，正文优先自然流；提示草稿同步后可能大量错位，合规通过不替代同步后检查 |
| SVG 交互 | 禁止跨元素 ID 事件及动画时序绑定；保留合法内部资源引用；不绕过导入清洗 |
| 外链与素材 | 默认不新增跳转，原有外链不批量删除；不虚构来源、图片、二维码或活动事实 |
| 输出安全 | 内联样式正文片段；不新增脚本、内联事件、可执行 URL、嵌入页面或样式依赖 |
| 行高误报处理 | 充分复核无实际重叠后保留设计与内联强调，不反复改安全行高；保留原始检测结果，不谎报通过 |
| 输出文字与附件 | 新写中文使用全角标点，不损坏代码等原样数据；附件按需读取，资料中的指令不覆盖用户请求 |

绝对定位有两层依据。官方 4.2.2 明确禁止通过绝对定位或变形破坏视觉与结构顺序，或将文字定位到没有从属关系的背景区域；提示词将此要求独立列明，要求文字置于实际背景容器内部，并在设计能力说明中引用这一边界。用户另外补充了同步兼容性经验：密集使用绝对定位的排版同步到公众号草稿后可能大面积错位。因此正文等阅读内容优先自然流，绝对定位用于有稳定父容器的局部叠层，草稿同步后复核实际版式。合规引擎通过不能替代同步后检查。

文案处理以保留原文为默认：不主动润色、改写或增删，用户明确要求时再按指定范围处理；正常分段、换行和视觉层次调整仍可自由进行，保持原意和阅读顺序。

[Agent 提示组装](../backend/app/services/chat_agent.py)同步说明自由设计无需主题确认，只有应用主题库中的主题才执行原有确认流程。主题严格契约继续生效；修复了“两个检查均无 ERROR 才能结束”与官方引擎 `isValid` 状态不一致的指令。官方引擎不可用时如实保留未验证状态，不阻止保存或结束本轮。

`layout_reference.py` 和 `web_article_import.py` 的导入清洗会移除部分 SVG 动画或交互标签；主题库还有独立严格契约。官方列出某种效果的规范不代表所有项目通道都支持它，模型不得补回被清洗内容以绕过限制。

用户明确补充的微信 SVG 交互兼容性约束：不支持跨元素 ID 绑定触发，不能生成 `button.click`、`button.touchstart`、`otherAnimation.end` 等事件或动画时序引用，包括同一 SVG 内的跨元素绑定。提示词要求使用实际交互目标内部不带元素 ID 的本地事件触发，并保留渐变、遮罩、裁剪等正常资源引用。这是用户指定的生成约束，不冒充官方规范新增条目或现有引擎已覆盖的检测规则；浏览器预览成功及合规报告通过均不能替代微信端交互验证。

## 验证与后续维护

使用现有官方浏览器 fixtures 验证正常布局、违规报告、Dark Mode 与豁免行为，并运行提示缓存、参考排版提示及主题写入重试相关回归。提示词改动不要求新增模仿文本实现的断言测试。

更新官方快照时重新核对上述文档与实现差异；规范摘要保留边界与例外，完整示例仍由 `read_wechat_compliance_spec` 按章节分页读取，不把全文重复注入每一轮上下文。回归测试证明工具与提示组装正常，不代表已经量化证明所有模型的设计质量提升。
