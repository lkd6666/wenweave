# 粘贴排版参考与文本附件

## 排版模仿

入口为“模仿排版”：文章链接、粘贴原文、HTML 源码，三个入口等宽。“粘贴原文”使用独立的富文本编辑区：剪贴板含 HTML 时立即显示安全的内联排版，可继续编辑、在光标处追加粘贴并撤销；修改文字不会转成纯文本。只有纯文本时安全转义并按换行分段，字面 HTML 标签作为文字显示。“HTML 源码”保留源码输入方式。

富文本先在惰性模板中清理脚本、事件、表单、iframe、导航元信息等主动内容，再显示在禁用脚本的隔离 iframe 中。CSP 阻止外部资源请求和表单提交，点击文章链接不会离开编辑区；合法的内嵌栅格图片可以直接显示。外部图片地址保留用于后续转存，在勾选并解析之前不会从编辑区发起下载。字号、颜色、对齐、间距等内联样式保留；外部样式表和动态脚本仍不参与还原。预览时清理不影响服务端继续校验提交的 HTML。

粘贴解析上限为 UTF-8 5MB。默认不请求外部图片地址，合法 data 图片直接保留。用户可勾选“转存外部图片”再解析，从公网 HTTP/HTTPS 下载图片（`//` 地址按 HTTPS 处理）；复用现有公网访问、DNS/重定向检查、内容格式校验、单图 10MB、全部图片 50MB 和 200 张上限，下载最多并发 4 个。同一图片在正文、CSS 背景、SVG 中重复出现时按地址去重。相对地址没有来源页面，无法自动补全；本地、内网、不可访问或不受支持的图片跳过并报告数量，已成功图片和排版继续保留。转存到临时参考素材后，仍需按原有流程选择图片并确认复用授权；应用时才复制为正式文档图片。切换输入方式会重置转存选项，改变转存选项会使当前预览失效，需要重新解析。

样式表及动态脚本不参与还原。需要浏览器渲染后的布局、登录态或防盗链图片时可使用文章链接或浏览器采集。

接口：`POST /api/layout-references/paste`，JSON 为 `{content, format: "text" | "html", title?, download_external_images?: boolean}`；`download_external_images` 默认为 `false`，为 `true` 时尝试转存外部图片，旧客户端省略时不下载。返回原有排版预览结构，后续确认流程复用现有实现。

## 长文本路径

1. 前端粘贴时按 UTF-8 字节估算 token；超过 `max(128, min(2000, 可用输入空间 / 8))` 时上传为文本附件，正文不会插入编辑器。普通输入在发送前再检查，后端也为旧客户端和队列输入提供兜底转换。此阈值只决定资料是否改为附件，不改变上下文压缩策略。
2. 上传存入独立 `chat_text_attachments` 表，正文延迟加载。每份最多 2MiB，每条消息最多 8 份；每用户最多 32 份未发送附件。上传时清理 7 天前的未发送草稿，已发送附件随消息生命周期保留。
3. 发消息只提交附件 ID；消息历史、浏览器草稿、初始模型请求及用户事件账本只保存附件元数据与读取指引。附件正文不作为整段消息参加压缩。后续按需读取的工具片段会正常进入工具历史并占用上下文预算。
4. `search_text_attachment(attachment_id, query, cursor?, limit?)` 做字面检索；`read_text_attachment(attachment_id, start?, end?)` 按 Unicode 字符范围分页，返回 `next_cursor`。两者均计算完整 JSON 输出的工具 token 预算。支持 v1、v2 工具协议。
5. 模型工具校验文档、当前会话、关联用户消息、归档/替代状态和上下文截断边界。附件路径是虚拟路径，没有任意文件系统访问或执行能力。正文与文件名作为不可信资料处理，模型提示也明确禁止其中指令覆盖真实要求。

上传状态为上传中、就绪、失败可重试。失败正文只留在内存以便重试；成功后移除内存中的待上传正文。浏览器持久化仅保存元数据。上传未完成或失败时阻止发送；成功草稿可从服务端恢复。发送失败、队列取消、编辑历史请求会保留引用；已发送附件复用时创建独立绑定，保持旧消息不可变。会话切换后旧异步结果不得写入新会话。

## HTTP 接口

- `POST /api/documents/{doc}/chat-texts`：multipart 的 `session_id` 与 UTF-8 `file`。
- `GET /api/documents/{doc}/chat-texts?session_id=...`：当前用户的未发送附件元数据。
- `GET /api/documents/{doc}/chat-texts/{id}?start=...`：有文档访问权限的前端分页预览，每页最多 8,000 字符且受 token 限制。
- `DELETE /api/documents/{doc}/chat-texts/{id}`：删除本人未发送草稿；已发送附件返回 409。
- 聊天发送及上下文预算预览增加 `text_attachment_ids`，最多 8 个。

例如粘贴 60,000 字的资料后，补充“仅检查第三章中金额与日期的矛盾”。初始请求只有这句要求和附件清单；模型先检索“第三章”、金额和日期，再读取相关范围。实际读取量由任务与命中结果决定，没有固定节省率保证。

## 部署与验证

本项目启动时已有 `Base.metadata.create_all`，注册新模型后会创建新表，既有表无字段迁移。另附 `backend/migrations/20261104_chat_text_attachments.mysql.sql` 供需要手工建表的 MySQL 部署审阅；不要与启动建表并发执行。无需迁移旧消息正文，旧历史保持原样。

专项测试覆盖富文本剪贴板、HTML 清理、内嵌图片、Unicode 无损分页、页面游标、上传恢复、跨会话异步所有权、消息重试和队列、正文不进入初始模型请求/用户账本/浏览器持久化，以及两套模型工具协议。浏览器验证使用本地生产构建和拦截 API 的离线 fixture，不代表真实模型完成任务或真实供应商缓存数据。
